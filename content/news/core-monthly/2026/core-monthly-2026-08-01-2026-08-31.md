Welcome to the August 2026 Core Monthly. After the intensity of July, this was a calmer month, the kind where a lot of people are away and the work that gets done is the work that keeps everything else standing.

![Core Monthly banner](/assets/images/theme/banner-core-monthly-wide.jpg)

Dear community,

August is traditionally the quietest month of the year for the project, and the numbers reflect it: 488 pull requests opened and 289 merged, against 705 and 434 in July. That is still a healthy amount of activity for a summer month, and what is interesting is where it went. There was no new feature announcement and no event, but there were two security releases, a large piece of architectural groundwork for 9.2, and a serious housekeeping pass across the whole module ecosystem. Let's walk through it.

## Two security releases, and the end of the 9.1.x line

On August 18th we published [PrestaShop 9.1.5]({{< relref "/news/releases/prestashop-9-1-5-security-release" >}}) and [PrestaShop 8.2.8]({{< relref "/news/releases/prestashop-8-2-8-security-release" >}}) on the same day, each fixing the same five vulnerabilities reported through coordinated disclosure.

![PrestaShop 9.1.5 is available](/assets/images/2026/08/9.1.5_1534x434.png)

The five issues are worth reading about in the release notes, because several of them are the kind that are easy to underestimate. Formula injection in CSV exports puts whoever opens the file at risk rather than the shop itself, which includes accountants and customers receiving a GDPR export. IP spoofing through the `X-Forwarded-For` header quietly undermines anything that trusts a visitor's address, from maintenance-mode allow-lists to rate limiting. None of them require an unusual setup to be exposed, so if you have not updated yet, this is the one thing in this article worth doing today.

![PrestaShop 8.2.8 is available](/assets/images/2026/08/banner_8.2.8_1534x424.jpg)

9.1.5 also carries around a hundred bug fixes, the largest batch the branch has received since 9.1.2, and it is the last planned release of the 9.1.x line before 9.2 arrives. That has a practical consequence you will see echoed all over the pull request list below: the `9.1.x` branch was deleted, and every repository that referenced it in its CI had to be pointed at a tag instead. If you maintain a module that tests against PrestaShop, it is a good moment to check that you are not still pointing at a branch that no longer exists.

## The import system is being rebuilt

The most significant piece of core work this month is not something you can see yet. [@jolelievre](https://github.com/jolelievre) opened [#42247](https://github.com/PrestaShop/PrestaShop/pull/42247), the first pull request in the import migration, which lands the architecture plan along with a new import engine and a `ProductImporter` built on top of it.

The legacy import controller has been one of those parts of the codebase everyone works around rather than with: a single large controller handling every entity type, with the parsing, the validation, and the persistence tangled together. The new engine separates those concerns and makes an importer something a module can provide, rather than something the core has to know about in advance. To show what that looks like in practice, a [demoentityimporter module](https://github.com/PrestaShop/example-modules/pull/256) was added to the [example modules](https://github.com/PrestaShop/example-modules) repository, implementing a custom importer against the 9.2 engine. If you have ever written an import routine for a custom entity, that module is the interesting read.

## The Symfony dashboard gets real charts

The migration of the back office dashboard to Symfony took a visible step forward this month. [@nicosomb](https://github.com/nicosomb) added [Chart.js as an independent core bundle](https://github.com/PrestaShop/PrestaShop/pull/42135) with a PrestaShop colour palette, which gives the migrated dashboard a charting library that modules can use too rather than each one shipping its own.

The rest of the work around it followed the pattern we like to see: a [dashexample module](https://github.com/PrestaShop/example-modules/pull/254) demonstrating the new Symfony dashboard hooks, [Chart.js examples added to it](https://github.com/PrestaShop/example-modules/pull/255), and the [hooks documented](https://github.com/PrestaShop/docs/pull/2159) in the developer documentation. A new extension point is only useful once someone can find out how to use it, and this time the example and the docs landed alongside the feature rather than months later.

## A very large housekeeping pass

A big share of August's merged pull requests were maintenance, and they are worth calling out precisely because they are the kind of work that never gets announced. Between them, [@mattgoud](https://github.com/mattgoud), [@jolelievre](https://github.com/jolelievre) and [@Progi1984](https://github.com/Progi1984) swept through more than forty native module repositories: repointing CI from the deleted `9.1.x` branch to a pinned tag, adding 9.2.x to the PHPStan matrices, migrating PHPStan and PHP-CS-Fixer to shared reusable actions, extending PHP support up to 8.5, and correcting README compatibility lines that had drifted years out of date.

Elsewhere in the tooling, the [test scenarios](https://github.com/PrestaShop/test-scenarios) repository was [migrated from Forge to JIRA Cloud](https://github.com/PrestaShop/test-scenarios/pull/911), the [Docker images](https://github.com/PrestaShop/docker) sync workflow was fixed, and a reusable [team-guard action](https://github.com/PrestaShop/.github/pull/52) was extracted from the AI review workflow so other workflows can use the same gate. The [contributors website](https://contributors.prestashop-project.org/) also gained a Top QA ranking with shareable cards, driven again by [@PrestaEdit](https://github.com/PrestaEdit) across [TopContributors](https://github.com/PrestaShop/TopContributors) and [traces](https://github.com/PrestaShop/traces).

## Faceted search kept getting better

The [faceted search module](https://github.com/PrestaShop/ps_facetedsearch) had its busiest month in a long while, with around a dozen merged pull requests. [@boo-code](https://github.com/boo-code) fixed the price filter so it matches the range the slider actually displays, made filter values sort in a locale-aware way, indexed prices for every active shop country, and fixed a price indexation loop that stopped early when product ids were not sequential. [@Hlavtox](https://github.com/Hlavtox) [optimised the performance of product listings](https://github.com/PrestaShop/ps_facetedsearch/pull/1303) and added an AND mode for feature filter checkboxes, which is one of those long-standing requests from merchants with detailed catalogues.

There is also a nice pair of changes worth noticing together: [@jf-viguier](https://github.com/jf-viguier) added [feature values at the combination level](https://github.com/PrestaShop/PrestaShop/pull/41830) in the core, and then made the faceted search [understand them in feature filters](https://github.com/PrestaShop/ps_facetedsearch/pull/1292). A core capability and the module change that makes it visible to shoppers, from the same contributor, is exactly how these things should land.

## PS Summit 2026 is in November

![PS Summit 2026](/assets/images/2026/05/PS_Summit_Buildblog.png)

A reminder while August was quiet: [PS Summit 2026]({{< relref "/news/posts/2026/ps-summit-2026-lyon-registrations-call-for-papers-workshops" >}}) takes place in Lyon on November 5th, the first joint event powered by PrestaShop and Sylius. The Call for Papers has closed and the programme is being assembled, but tickets are still available and still free.

The day before the conference there is a cross-community workshop where PrestaShop developers can learn the foundations of Sylius and vice versa, followed by a joint hackathon in the afternoon. Seats are limited and the workshop requires a separate registration from the conference, so if you have been putting it off, now is a good time to sort it out.

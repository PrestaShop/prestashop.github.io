Welcome to the October 2026 Core Monthly. With PrestaShop 9.2 out of the door, October was a month of consolidation: the Admin API took a big step towards maturity, the performance work picked up speed, and the 9.2.x branch collected a solid batch of fixes.

![Core Monthly banner](/assets/images/theme/banner-core-monthly-wide.jpg)

Dear community,

After a month as intense as September, you might expect things to slow down a little. They did not, they just changed direction. Instead of shipping a big release, October was about listening to the first feedback on 9.2, hardening what we just published, and preparing the ground for what comes next on `develop`. In total, 170 pull requests were merged by 31 contributors, and a good share of them came from the community. Here is what stood out.

## The Admin API is growing up

The Admin API was one of the busiest areas of the month, and most of that work was about turning a promising feature into a contract that module developers and integrators can rely on. [@jolelievre](https://github.com/jolelievre) updated [ADR 0023](https://github.com/PrestaShop/ADR) to write down the rules the API now follows: resources live in the [ps_apiresources](https://github.com/PrestaShop/ps_apiresources) module, lists share the same paginated format, and bulk operations and status codes behave consistently everywhere. Writing these decisions down matters, because it is what lets several people add endpoints in parallel without each of them reinventing the conventions.

Concretely, every endpoint now requires a scope, which closes the door to resources accidentally exposed without permission checks. The missing Product endpoints were added, the experimental multistore support got its own documentation section, and a scheduled workflow now keeps the API tracking issue up to date every day, so anyone can see at a glance what is covered and what is still missing. On the community side, [@PrestaEdit](https://github.com/PrestaEdit) consolidated the Country, Customer and ImageType endpoints into single domain pull requests, which makes them much easier to review and merge.

You will also notice a few PRs tagged "AI context" in the list below. The core and ps_apiresources repositories now ship context files, review checklists and conventions extracted from past reviews, so that AI assistants (and humans!) contributing to the codebase start from the same rules the maintainers apply. It is a natural follow-up to the work we described in [Teaching AI to speak PrestaShop]({{< relref "/news/posts/2026/teaching-ai-to-speak-prestashop" >}}).

## Performance, one query at a time

[@LameuleFR](https://github.com/LameuleFR) had a very productive month hunting down unnecessary work. On `develop`, the translator now only warms up the catalogues of installed languages, shop translations are saved with one query per language instead of one per string, upgrading a single module no longer loads every module present on disk, and the front office skips the cart quantity query when the cart has not even been saved yet. On the 9.2.x side, the out-of-stock label now reuses the quantities that are already computed, and in the [Faceted search module](https://github.com/PrestaShop/ps_facetedsearch) uncached category pages run fewer and lighter SQL queries.

None of these changes is spectacular on its own, and that is precisely the point: performance on a real shop is rarely about one big fix, it is about removing dozens of small costs that add up on every page view. If you have spotted a slow area in your own shop, this is a great example of how to contribute a targeted, easy-to-review improvement.

## New features on the develop branch

While 9.2.x received fixes, `develop` kept moving towards the next version. [@soledis-contributeur](https://github.com/soledis-contributeur) added the edit and deletion pages for business entities in the back office. Carrier tracking URLs can now use order and delivery address placeholders, which is handy for carriers that need more than a tracking number to show the parcel status. [@Codencode](https://github.com/Codencode) added automatic cleanup of outdated sessions, so the sessions table no longer grows forever, and the Docker Compose setup now accepts environment variables, making it possible to run several PrestaShop instances side by side when you develop or test.

Security hardening was also on the menu: password reset tokens are now generated with a cryptographically secure random generator, thanks to [@nabhan06](https://github.com/nabhan06), and CLI commands now run with an anonymous employee instead of borrowing the identity of employee 42, a fix from [@Jeremie-Kiwik](https://github.com/Jeremie-Kiwik).

## Modules, themes and tooling

The [ps_onepagecheckout](https://github.com/PrestaShop/ps_onepagecheckout) module keeps getting polished after its debut in 9.2: the payment section and the footer are now aligned with the checkout form on desktop, and the configuration page warns merchants when guest checkout is disabled. The [Product Comments module](https://github.com/PrestaShop/productcomments) 9.0.1 and the [Email subscription module](https://github.com/PrestaShop/ps_emailsubscription) 3.0.1 were released, the latter with missing database indexes contributed by [@Prestaplugins](https://github.com/Prestaplugins). [@kpodemski](https://github.com/kpodemski) replaced the old webpack, Babel and node-sass toolchain of the faceted search with esbuild and Dart Sass, a welcome modernization for anyone building the module's assets.

[PrestaShop Flashlight](https://github.com/PrestaShop/prestashop-flashlight) also had a busy month, with [@Alexandre-Lematre](https://github.com/Alexandre-Lematre) fixing builds for older PrestaShop versions, the Alpine Apache images and the nginx routing of language-prefixed URLs. Finally, a warm welcome to Benjamin Bendaoui, who joined the list of [project committers](https://github.com/PrestaShop/open-source) this month.

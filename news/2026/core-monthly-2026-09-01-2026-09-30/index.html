    PrestaShop Core Monthly - September 2026

    PrestaShop 9.2 ships with Hummingbird 2.1.2, a wave of native module releases, and one month to go before PS Summit

    Written by
    Marco Salvatore
    Solution Engineer
    Published

    Oct 8, 2026

    Share this

    Welcome to the September 2026 Core Monthly. This is the month PrestaShop 9.2 went from release candidate to stable, and most of what happened in the repositories was, one way or another, about getting it out of the door in good shape.

    Dear community,

    Some months are about laying foundations, and some are about shipping. September was firmly the second kind. In the space of nine days we published the first release candidate and then the stable version of PrestaShop 9.2, released Hummingbird 2.1.2 alongside it, and pushed out a batch of native module updates so that everything in the bundle lines up. In total, 229 pull requests were merged by 26 contributors. And while the 9.2.x branch was being polished, the develop branch kept moving towards the next version. Let’s walk through it.

    PrestaShop 9.2 is here

    On September 21st we opened PrestaShop 9.2 RC1 for testing, and on September 30th PrestaShop 9.2 became available as a stable release. A short gap like that between the two only happens when the release candidate holds up well, so a big thank you to everyone who installed it, tested it and reported back.

    If you have followed the blog this year, the headline features will sound familiar. A native One Page Checkout module now ships in the bundle, and merchants can switch between the one-page and the four-page flow from the back office. Ask AI brings a conversational assistant into the back office, powered by the PrestaShop MCP Server. Another batch of pages has been migrated to Symfony behind a feature flag, and image types gained a new thumbnail fitment setting, contributed by @Hlavtox and sponsored by TRENDO s.r.o. The release article has all the details and screenshots, and if you maintain a payment or carrier module, it also links to the guides you need to check your module against the one-page flow.

    The Update Assistant kept pace with the release: version 7.6.6 came out on September 29th with full support for PrestaShop 9.2, so shops running 9.0.x or 9.1.x can update right away. Getting there took a good part of the month, with the 9.2.0 upgrade script now creating the new Extra Properties tables, more permissive detection of module upgrade files, clearer wording for modules whose compatibility cannot be confirmed, and a fix from @rboadalabelgrup so that a locked cache file no longer aborts an upgrade. As always, back up your shop and try the update on a staging environment first, and note that if you were testing the RC1, you will need a fresh installation of the final release.

    Extra Properties got its final polish

    Extra Properties is the 9.2 feature developers will probably feel the most, since it gives modules a single, native way to attach custom fields to core entities. Because it becomes a public extension point the moment 9.2 ships, a lot of September went into making sure it was solid before anyone builds on it.

    @jolelievre added the ability to restrict a definition to a list of shops, so a module’s properties follow the shops where that module is enabled, and handled the less conventional cases such as entities with irregular naming and the cart entity. The most important change, though, came from @Jeremie-Kiwik: validation constraints used to be stored with PHP serialization, and they are now stored as the same small DSL that the back office “Validation” field already shows. Reading a definition back no longer goes through unserialize(), which removes a whole class of risk instead of trying to guard it. The feature now has its developer documentation, its endpoints in ps_apiresources 0.9.0, and a renamed demoextraproperty module in the example modules repository showing how to register properties on carts, orders and combinations.

    Hummingbird 2.1.2

    Hummingbird, the default theme since 9.1, shipped two maintenance releases this month, 2.1.1 and then 2.1.2, which is the version bundled with PrestaShop 9.2. Most of the changes are the kind shoppers only notice when they are missing. The checkout address step no longer nests forms (which broke the Continue button when editing a separate billing address), the guest order tracking form now submits with POST, the country tax label setting is respected on the product page, and the reassurance icons are marked as decorative for screen readers. Many of those fixes came from @boo-code. The theme also takes advantage of the new thumbnail fitment with a dedicated image type for brand logos on the product page, and 2.1.2 removes development files from the package for security.

    On the tooling side, @tblivet added a QA testing checklist covering a full theme test pass, and turned it into a Hummingbird QA skill for AI agents in the new PrestaShop skills repository, next to a more general skill that guides an agent through the QA of a pull request. Both are still young, so feedback from people actually using them is very welcome. Note that building the theme from source now requires Node.js 24, which does not affect shops using the packaged theme.

    A wave of native module releases

    A new minor version is also the moment to bring the native modules in line, and September saw a lot of that. contactform 5.0.0, productcomments 9.0.0, ps_banner, ps_cashondelivery and ps_wirepayment 3.0.0, and ps_facetedsearch 5.1.0 were all released, and ps_imageslider, ps_socialfollow and ps_faviconnotificationbo were aligned on PrestaShop 8.2+ and are ready for their own releases. The major version bumps mostly reflect that alignment: dropping support for very old PrestaShop versions lets these modules shed compatibility code and use the modern APIs, which makes them easier to maintain and easier for contributors to work on.

    Meanwhile, on develop

    While 9.2.x was being stabilized, the develop branch kept moving. @Quetzacoalt91 merged the migration of the Stores page to Symfony, and it is an interesting one: it was built with the help of the migration skill provided in the repository, then refined over a few iterations, which is a good sign that the investment in documenting how a migration should look is starting to pay off. The same contributor also upgraded the core from PHPStan 1 to PHPStan 2, a stricter analysis that will catch more problems before they reach a release.

    The import rebuild we talked about last month reached its second step, with @mattgoud adding the CQRS layer that drives import jobs and lets a job resume where it stopped across several requests, while @jolelievre split the product importer into smaller, per-concern steps. @nicosomb improved the carrier domain and added the carrier endpoints to the Admin API, and @soledis-contributeur added the business entities listing and detail pages to the back office, behind the existing B2B feature flag.

    There is also a piece of work aimed at contributors’ daily lives. Our UI test campaigns are retried automatically, and a pull request is often green only after a couple of attempts, which is slow and frustrating for everyone. @jolelievre built a collector and a statistics dashboard that read campaign results back from the GitHub API, including the runs on contributor forks, to show which campaigns are flaky and how much machine time the retries cost. The goal is to spend the last quarter of the year fixing the worst offenders, based on data rather than gut feeling.

    See you in Lyon next month

    PS Summit 2026 is now just a month away. On November 4th, the workshop and hackathon day brings PrestaShop and Sylius developers together, with hands-on sessions in the morning and a cross-framework hackathon in the afternoon. On November 5th, the conference opens at the Palais des Congrès in Lyon with a keynote that promises a first look at PrestaShop 10 and Sylius 3. The programme is being finalised and we will share more about it in the coming weeks. If you have not registered yet, remember that the workshop and the conference need separate registrations, and workshop seats are limited. We would love to see many of you there.

    Most active contributors

    1. @jolelievre (35 PRs) wore a lot of hats this month: the last round of Extra Properties hardening and its documentation, the ps_apiresources 0.9.0 release, the 9.2.0 release itself in the distribution API, the import engine refactor on develop, and the flaky test dashboard in ga.tests.ui.pr.
    2. @boo-code (24 PRs) fixed a long list of multishop and combination bugs in the core, made the installer move the admin folder across devices instead of failing, contributed several Hummingbird checkout and accessibility fixes, and clarified two topics in the developer documentation.
    3. @Quetzacoalt91 (17 PRs) split their time between the Update Assistant, the productcomments 9.0.0 release, the Stores page migration and the PHPStan 2 upgrade.
    4. @tblivet (13 PRs) released Hummingbird 2.1.1 and 2.1.2, wrote the theme QA checklist and the first QA skills in the skills repository, and improved the core build scripts.
    5. @mattgoud (12 PRs) released ps_facetedsearch 5.1.0, aligned three more native modules on PrestaShop 8.2+, fixed several Shipment domain defects and delivered the import job CQRS layer.

    Spotlight on community contributors

    Every month we highlight a few contributors from outside the core team whose work made a difference. Here are five of them for September.

    • @boo-code was once again everywhere, fixing CMS links and content on multishop, editing combinations with NULL identifiers, the unit price impact in bulk combination edits, and a handful of Hummingbird checkout issues that made it into 2.1.2.
    • @Codencode fixed a performance regression on the Carts page, PHP 8.5 deprecations in the core and in the faceted search, a payment that kept only the first 9 characters of the order reference, and the delivery option cache when a delivery address changes.
    • @Hlavtox enriched the core structured data with product features and shop contact details, kept pagination in hreflang URLs, made it possible to keep working on an order once it is shipped, and released contactform 5.0.0.
    • @PrestaEdit improved how companies are ranked and credited on the contributors website across TopContributors and traces.
    • @Jeremie-Kiwik replaced PHP serialization with a DSL for Extra Properties constraints, an important security hardening that landed just in time for 9.2.

Take a scroll, there is something for everyone.
